# Разработать многопользовательскую игру с чатом

## Требования

- Игрок подключается к серверу по известному адресу (`ws://...`, `ip:port`, `http://...`).
- При подключении игрок выбирает себе имя.
- После входа в игру персонаж игрока отображается на двумерной карте в виде примитива. Цвет персонажа и его начальную позицию сервер выбирает таким образом, чтобы различать игроков.
- Игрок может перемещать своего персонажа по карте с помощью стрелок.
- Игрок может написать сообщение в общий чат.
- Игроки, подключённые к серверу, видят сообщение рядом с персонажем отправителя, а также в общем списке сообщений.

## Технологии

- Клиент: Unity.
- Сервер: Kotlin.

## Условие выполнения

**Код должен написать соискатель, а не нейросеть.**

## Осознанные упрощения

Перечисленные ниже ограничения - намеренные компромиссы в пользу простоты реализации

### Чат и интерфейс

- Локальные сообщения не поддерживаются: сообщение отправляется только через сервер
- История чата не сохраняется и теряется после выхода из комнаты
- Фокус на поле ввода чата не блокирует управление персонажем
- Нет ограничений на сообщения, защита от спама не реализована

### Игровая логика

- В комнате действует жестко заданный лимит в 10 игроков
- Используются фиксированные точки появления персонажей
- Сервер принимает координаты от клиента без проверки скорости, границ карты и столкновений
- Античит не предусмотрен

### Сеть и безопасность

- Данные передаются в открытом виде
- Пинг не измеряется и не компенсируется
- Восстановление сессии и автоматическое переподключение не поддерживаются
- Нет ограничений на размер и частоту запросов
- Запросы не оптимальны, сейчас нагрузка на сеть может быть значительной

### Серверная архитектура

- Поддерживается только одна игровая комната
- Синхронизация позиции выполняется часто и может создавать неоптимальную нагрузку на сервер
- Нет гарантии доставки сообщений
- Нет мониторинга и health-check проверок
- Ошибки протокола игнорируются и не обрабатываются

### Тестирование

- Покрытие тестами небольшое
- Нет нагрузочных, интеграционных, сетевых и security-тестов

### Общее

- Конфигурация местами негибкая
